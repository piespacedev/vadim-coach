# Лендинг тренера — MVP-макет

Одностраничный сайт: первый экран с анимированным заголовком, «Обо мне»,
«Программы», «Результаты» и «Контакты» с формой заявки (заявки приходят в Telegram-бот).
Адаптив: телефон / планшет / десктоп.

## Запуск

```bash
npm install
npm run dev
```

Сборка для публикации: `npm run build` → готовые файлы в папке `dist/`.
Перед сборкой запускается проверка типов (`tsc`) — она ловит забытые переводы.

Весь текст сайта — в одном файле **`src/content/site.ts`**, сразу на двух языках.
Вёрстку трогать не нужно, правится только он:

| Что                                        | Где в `src/content/site.ts` |
| ------------------------------------------ | --------------------------- |
| Тексты на русском                          | объект `ru`                 |
| Тексты на английском                       | объект `en` (та же структура) |
| Имя-логотип, контакты, ссылки в подвале    | `brand` — не переводится    |
| Пути к картинкам                           | `images`                    |

Внутри `ru` и `en` тексты разложены по секциям:

### Заголовок первого экрана

Собирается по словам, каждое слово выезжает отдельно:

```ts
title: [
  [{ text: 'Сильнее' }],                                     // белое слово
  [{ text: 'с', dim: true }, { text: 'каждой', dim: true }], // приглушённые (45% белого)
  [{ text: 'тренировкой' }],
]
```

Каждый вложенный массив — отдельная строка заголовка. Слова появляются по
очереди с шагом 0.1 сек, задержки проставляет `Hero.jsx`.

### Карточки в центральной плитке

Листаются сами каждые 3.5 сек. `icon` — имя иконки из
[lucide.dev/icons](https://lucide.dev/icons); иконка должна быть добавлена в
объект `ICONS` в `Panels.jsx`, `color` — класс фона кружка. `icon` и `color`
в `ru` и `en` одинаковые.

## Языки RU / EN

Переключатель RU | EN — [src/components/LanguageToggle.tsx](src/components/LanguageToggle.tsx).
На экранах от 1024px он в шапке справа и в выезжающей панели рядом с кнопкой
«Записаться»; на телефоне и планшете — внутри бургер-меню.

- **Язык по умолчанию:** сначала сохранённый выбор (localStorage, ключ
  `coach-landing:lang`), потом язык браузера: `ru…` → RU, всё остальное → EN.
- **При смене языка** обновляются `<html lang>`, заголовок вкладки и
  `meta description`, выбор запоминается.
- **Библиотек i18n нет:** контекст и хук `useLang()` — в
  [src/lib/i18n.tsx](src/lib/i18n.tsx), словари — в `src/content/site.ts`.

Как добавить новый текст:

1. Добавить поле в тип `Copy` в `site.ts`.
2. Заполнить его в `ru` и в `en`.
3. В компоненте: `const { t } = useLang()` → `{t.hero.title}`.

Если забыть английский вариант, `npm run build` остановится с ошибкой
TypeScript — пустого места на сайте не будет. Всё, что не переводится
(телефон, ссылки), кладётся в `brand`; если поле бренда всё же зависит от
языка, оно пишется как `{ ru: '…', en: '…' }` и читается как `brand.field[lang]`.

## Форма заявки → Telegram-бот

Сайт живёт на Vercel, бот — на своём VPS. Форма отправляет заявку боту
[@vadimzayavkabot](https://t.me/vadimzayavkabot) на
`https://vadim-bot.201-34-132-115.sslip.io/api/lead`, а он пересылает её в группу
**«Вадим заявки с сайта»** (`-5260260971`). На Vercel ничего настраивать не нужно:
токен бота хранится только на VPS.

**Доступ к заявкам — только у id `682100278` и `8699350672`.** Группа и список админов —
в начале [server/telegram.js](server/telegram.js).

- Заявки уходят только в эту группу — её id зашит в коде. Если кто-то найдёт бота и добавит
  его в свою группу, туда ничего не придёт, а бот сразу из неё выйдет.
- Заявки бот нигде не хранит, команд «показать заявки» у него нет.
- В личке бот отвечает админам «всё подключено», остальным — что он закрытый.
- Посторонних, добавленных в группу заявок, бот удаляет сам — если он в группе админ
  с правом банить.

От спама: скрытое поле-ловушка, ограничение длины полей и не больше 5 заявок в минуту
с одного адреса (nginx). Если отправить не вышло, посетитель видит ошибку с предложением
написать в Telegram или WhatsApp — заявка не «пропадает молча».

- `npm run bot:check` — кто в группе, нет ли посторонних, тестовое сообщение в группу.
- `npm run dev` — форма работает и локально: заявку принимает dev-сервер Vite с токеном
  из `.env.local` (файл не попадает в git) и отправляет в группу по-настоящему.

Если Telegram превратит группу в супергруппу (так бывает при выдаче боту прав админа),
у неё сменится id. Заявки всё равно дойдут, а `npm run bot:check` подскажет новый id
для `LEADS_CHAT_ID`.

| Файл                    | Что делает                                                     |
| ----------------------- | -------------------------------------------------------------- |
| `server/telegram.js`    | группа и админы, текст заявки, отправка, защита группы         |
| `server/lead-route.js`  | `POST /api/lead` — общий для бота на VPS и `npm run dev`       |
| `server/index.js`       | бот на VPS: приём заявок + long polling                        |
| `scripts/bot.mjs`       | `npm run bot:check`                                            |
| `deploy/`               | служба systemd и конфиг nginx для VPS                          |

## Бот на VPS

Сервер `201.34.132.115` (Ubuntu, nginx, Node 24), рядом живут другие проекты.

```
/opt/vadim-bot/
  server/   код бота — служба vadim-bot, порт 127.0.0.1:3300
  .env      TELEGRAM_BOT_TOKEN, PORT, TELEGRAM_IP_FAMILY=6 — доступ только у root и vadimbot
```

Снаружи — nginx: `https://vadim-bot.201-34-132-115.sslip.io/api/lead`, остальное — 404.
Сертификат Let's Encrypt продлевается сам (certbot).

С VPS до `api.telegram.org` по IPv4 не достучаться, только по IPv6 — поэтому
`TELEGRAM_IP_FAMILY=6`. Новое IPv6-соединение изредка виснет: бот ждёт ответа 3 секунды
и повторяет запрос, до 4 попыток.

- **Обновить бота:** `npm run deploy:bot` — зальёт `server/` и перезапустит службу
  ([scripts/deploy-bot.sh](scripts/deploy-bot.sh)).
- **Логи:** `journalctl -u vadim-bot -f`.

Первая установка (уже сделана): системный пользователь `vadimbot`, папка `/opt/vadim-bot`,
`.env` по образцу `.env.example` (`chown root:vadimbot`, `chmod 640`),
[deploy/vadim-bot.service](deploy/vadim-bot.service) → `/etc/systemd/system/`,
[deploy/nginx.conf](deploy/nginx.conf) → `/etc/nginx/sites-available/vadim-bot`
+ ссылка в `sites-enabled`, сертификат —
`certbot certonly --webroot -w /var/www/html -d vadim-bot.201-34-132-115.sslip.io`.

# GlareCard (shadcn-компонент)

## Что было настроено под него

Проект изначально был на Vite + JSX без TypeScript и без структуры shadcn.
Добавлено:

| Что                      | Файл                                    |
| ------------------------ | --------------------------------------- |
| TypeScript (рядом с JSX) | `tsconfig.json`, `allowJs: true`        |
| Алиас `@/` → `src/`      | `tsconfig.json` + `vite.config.ts`      |
| Хелпер `cn()`            | `src/lib/utils.ts` (clsx + tailwind-merge) |
| Конфиг shadcn CLI        | `components.json`                       |
| Папка ui-компонентов     | `src/components/ui/`                    |

Существующие `.jsx` продолжают работать: `allowJs` разрешает обоим форматам
жить в одном проекте, переписывать старые файлы на TypeScript не нужно.

Проверка типов: `npm run typecheck`.

### Почему именно `components/ui`

Этот путь прописан в `components.json` в `aliases.ui`. Команда
`npx shadcn@latest add <компонент>` кладёт файлы именно туда, и все сгенерированные
компоненты импортируют друг друга как `@/components/ui/...`. Если переименовать
папку, CLI будет создавать её заново, а импорты в скачанных компонентах поломаются.
Разделение простое: `components/ui/` — переиспользуемые примитивы без бизнес-логики,
`components/` — секции конкретно этого сайта.

## Использование

```tsx
import { GlareCard } from '@/components/ui/glare-cards'

<GlareCard tiltIntensity={8} glareColor="rgba(110, 231, 183, 0.28)" className="h-full p-6">
  <div className="flex h-full flex-col">...</div>
</GlareCard>
```

| Проп            | Тип      | По умолчанию              | Что делает                              |
| --------------- | -------- | ------------------------- | --------------------------------------- |
| `tiltIntensity` | `number` | `15`                      | Максимальный наклон в градусах          |
| `glareColor`    | `string` | `rgba(255,255,255,0.2)`   | Цвет блика и свечения по краю           |
| `className`     | `string` | —                         | Перекрывает дефолтные классы через `cn` |

Компонент сам уважает системную настройку «уменьшить движение»: при её
включении наклон и сдвиг блика отключаются.

Своя обёртка `<div className="flex h-full flex-col">` внутри нужна потому, что
GlareCard кладёт детей в собственный контейнер — `flex` на самой карточке до
содержимого не дойдёт.

## Где применён

Карточки в секции «Программы» — [src/components/Programs.jsx](src/components/Programs.jsx).
Чтобы откатить, достаточно убрать обёртку `<GlareCard>` и вернуть классы карточки
на `Reveal`.

## Отличия от исходного кода компонента

Исходник был написан под Next.js и в таком виде на Vite не работал:

1. **Наклон и блик были статичными.** Значения строились как
   `` useMotionTemplate`${springX.get() * ...}` `` — `.get()` читает число один раз
   на рендере, а пружина живёт вне React. Заменено на `useTransform`.
2. **`perspective: 1000`** в `style` действует на детей, а наклоняется сам элемент.
   Заменено на `transformPerspective: 1000`.
3. **Маска свечения по краю** не давала кольца: обоим слоям нужен разный box.
   Добавлен `content-box` первому слою и `-webkit-mask-composite: xor`.
4. `next/image` в демо заменён на `<img>` с фото Unsplash.
5. В тип пропсов добавлен `Omit` для `onAnimationStart`/`onDrag*` — у DOM и у
   framer-motion эти обработчики называются одинаково, но принимают разное.

# Шрифты: Panchang + Unbounded

`Panchang` (Fontshare) подключён в [index.html](index.html) и стоит первым в
`fontFamily.display`. **Кириллицы в нём нет** — проверено разбором таблицы
`cmap` его TTF: из 64 символов А–я покрыто 0, латиница на месте.

Дорисовать кириллицу к чужому дисплейному шрифту — это работа шрифтового
дизайнера, а не пара скриптов: половину букв (Б, Д, Ж, З, И, Л, Ф, Ц, Ч, Щ, Ъ,
Ы, Ь, Э, Ю, Я и строчные) из латинских контуров не собрать, они получатся
кривыми и это будет видно в заголовке на весь экран.

Поэтому пара: **Panchang — латиница, Unbounded — кириллица**. Оба широкие
геометрические дисплейные, по характеру совпадают. Браузер подбирает шрифт
посимвольно, так что смешанная строка («VADIM» + «Сильнее») рендерится сама:

```js
display: ['Panchang', 'Unbounded', '"DM Sans"', 'system-ui', 'sans-serif']
```

Unbounded заметно шире DM Sans, поэтому кегли заголовков пересчитаны вниз
(первый экран, плитки, заголовки секций, карточки).

Если захотите именно Panchang с кириллицей — это заказ шрифтовому дизайнеру
на кириллический комплект, либо покупка готового шрифта с обоими алфавитами.

# FAQ (shadcn-компонент)

- [src/components/ui/text-reveal-faqs.tsx](src/components/ui/text-reveal-faqs.tsx) — сам компонент
- [src/components/ui/accordion.tsx](src/components/ui/accordion.tsx) — аккордеон shadcn на Radix
- [src/components/Faq.jsx](src/components/Faq.jsx) — обёртка, ставит его на фон секции
- вопросы и ответы — в `faq` в [src/content/site.ts](src/content/site.ts) (в `ru` и `en`)

Ответ проявляется побуквенно при раскрытии пункта.

Что изменено против исходника:

1. `next/link` → обычный `<a>` (проекта на Next здесь нет).
2. Тексты вынесены в пропсы и приходят из словаря `faq` в `site.ts`,
   как и остальной сайт. Русских дефолтов внутри компонента нет.
3. **Исправлен перенос строк.** Каждая буква — `inline-block`, поэтому строка
   рвалась посреди слова. Буквы собраны в слова, между словами — обычный
   пробел текстом (внутри `whitespace-nowrap` он точку переноса не создаёт).
4. Добавлен `text-foreground` секции: без него вопросы наследовали чёрный цвет
   и на тёмном фоне были почти не видны.

Под компонент в проект добавлены токены shadcn (`--background`, `--foreground`,
`--muted-foreground`, `--primary`, `--border`) в [src/index.css](src/index.css)
и цвета в [tailwind.config.js](tailwind.config.js). На `<html>` стоит класс
`dark`, поэтому подставляются тёмные значения. Фон `body` намеренно не
переопределён — у сайта свой. Там же лежат keyframes `accordion-down/up`
(проект на Tailwind 3, поэтому они в конфиге, а не в `@theme` из Tailwind 4).
